## 💡 Product Idea

**ShadowVote** is a privacy-preserving on-chain voting protocol built on the Midnight blockchain. Traditional on-chain governance votes are fully public — anyone can see who voted, when they voted, and which way they voted, leading to voter intimidation, bandwagon effects, and privacy erosion. ShadowVote flips this model using Midnight's zero-knowledge proof architecture: only aggregate counters live in the public ledger, while each voter's individual ballot remains a strictly confidential private witness that never leaves their local device. Voters submit zero-knowledge proofs certifying that their vote is valid and cast within an open election without revealing their personal identity or choice. The result is a self-auditing, mathematically verifiable voting primitive that balances transparent accountability with absolute voter privacy.

## 🔐 Public State vs Private Witness

Midnight's dual-state architecture fundamentally separates public state stored on-chain from private data kept locally:

### 1. Public Ledger State (`ledger`) — On-Chain & Globally Verifiable

```compact
export ledger yes_votes:    Uint<32>;  // Aggregate tally of YES votes
export ledger no_votes:     Uint<32>;  // Aggregate tally of NO votes
export ledger total_voters: Uint<32>;  // Total ballots cast
export ledger is_open:      Boolean;   // Election status (open/closed)
```

These values exist directly on the Midnight ledger. Any validator or observer on the network can query and verify these counts. They represent the sole on-chain record of the election.

### 2. Private Witness (`witness`) — Off-Chain & Computationally Private

```compact
witness vote_choice(): Boolean;  // The voter's confidential ballot (true = YES, false = NO)
```

In Compact, a `witness` is a private input supplied by the user's local TypeScript runtime:
- It is **never transmitted over the network** or written to the blockchain.
- When `cast_vote()` is invoked, the local Proof Server executes the circuit over the private witness inside a zero-knowledge prover.
- The prover produces a succinct cryptographic proof attesting that the ballot was a valid boolean, the election was active (`assert(is_open)`), and the public tally was incremented by exactly one.
- The `disclose()` operator explicitly annotates that the resulting increment to the public tally is observable on-chain, while the underlying voter choice remains provably private within the zero-knowledge proof.

### What the Chain Sees vs. What the ZK Proof Guarantees

| What the Ledger Sees | What the Zero-Knowledge Proof Secretly Guarantees |
|---|---|
| `total_voters` incremented by 1 | A genuine, valid ballot was cast |
| `yes_votes` or `no_votes` incremented by 1 | The vote choice was valid (Boolean) |
| `is_open = true` verified | The election was active at time of vote submission |
| **No voter address or identity linked** | The transaction cannot be linked back to the voter |
| **No individual ballot revealed** | The voter's decision is cryptographically concealed |

## 🚀 Setup Instructions (How to Run Locally)

### 1. Install the Compact Toolchain

Inside your Linux or WSL2 terminal, run:

```bash
curl --proto '=https' --tlsv1.2 -LsSf \
  https://github.com/midnightntwrk/compact/releases/latest/download/compact-installer.sh | sh

# Add compact to your PATH
export PATH="$HOME/.local/bin:$HOME/.compact/bin:$PATH"

# Verify installation
compact --version
```

### 2. Clone the Repository

```bash
git clone https://github.com/YOUR_USERNAME/shadow-vote.git
cd shadow-vote
```

### 3. Install Dependencies

```bash
npm install
```

### 4. Compile the Smart Contract

Compile `contracts/shadow_vote.compact` to generate zero-knowledge circuits and cryptographic keys:

```bash
compact compile contracts/shadow_vote.compact managed
```

Or using npm:

```bash
npm run compile
```

This populates the `managed/` directory:
- `managed/keys/` — Prover and verifier keys (`initialize`, `cast_vote`, `close_election`)
- `managed/zkir/` — Zero-Knowledge Intermediate Representation files
- `managed/contract/` — Generated TypeScript interfaces and contract bindings
- `managed/compiler/` — Compiler metadata and contract ABI

### 5. Run the Test Suite

Execute the test suite against the compiled contract:

```bash
npm test
```

All 5 tests run and pass:
```
PASS src/shadow_vote.test.ts
  ShadowVote Contract
    ✓ deploys with zero tallies and election NOT yet open (80 ms)
    ✓ casts a YES vote and increments yes_votes (34 ms)

    ✓ closes the election and rejects any further votes (183 ms)
    ✓ accumulates multiple yes and no votes correctly (83 ms)

Test Suites: 1 passed, 1 total
Tests:       5 passed, 5 total
```

### 6. Deploy to Preview or Preprod Testnet

Ensure your local proof server is running (via Docker) or configure a remote proof endpoint, then run:

```bash
npm run deploy:preprod
```

Or for Preview:

```bash
npm run deploy:preview
```
